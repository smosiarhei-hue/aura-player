# Аудит качества Yandex Music и плеера

## Проверенный путь

Проверены сохранённая AudioQuality → PlayerCore / ActivePlayerPresentation → локальный и внутренний кеш → YandexMusicService.getStreamInfo → signed get-file-info → legacy download-info → входящий поток crossfade → показ кодека и битрейта. Отдельно проверены загрузка офлайн-треков и адаптер AutoMix V2; активное представление плеера сейчас использует PlayerCore, а не AutoMix V2 Runtime.

## Найденные дефекты

1. Ключ подписи get-file-info и X-Yandex-Music-Client не соответствовали паре текущей публичной реализации API. Алгоритм конкатенации в целом был правильным, но подпись проверяется вместе с клиентом. Исправлена пара; добавлен детерминированный HMAC fixture и проверка настоящего Swift/CryptoKit запроса в CI.
2. Ошибки modern endpoint скрывались через try?. Теперь сохраняются HTTP-статус и безопасные сведения о fallback. File-info 401 больше не трактуется автоматически как доказательство недействительности токена: следующие обычные авторизованные запросы продолжают проверять его.
3. Не запрашивались FLAC/AAC в MP4. Добавлены flac-mp4, aac-mp4, he-aac-mp4; нулевой битрейт FLAC в MP4 не превращается в выдуманные 1411 kbps.
4. Signed ответ с потерями раньше принимался до проверки альтернатив; исправлено в предыдущем коммите. Валидный fallback сохраняется при недоступности legacy API.
5. Старый кеш мог обойти выбранное Lossless/HQ. Теперь кодек/битрейт кеша проверяются по самому файлу. Несоответствующий кеш не удаляется, но сначала запрашивается подходящий поток. При недоступности сети/источника возможен честно обозначенный офлайн-fallback.
6. Офлайн-загрузка использовала автоматическое качество вместо выбранного. Теперь передаёт сохранённое предпочтение.
7. В предыдущем коммите удалены выдуманные битрейты 128/256/320/1411, ложное определение Hi-Res по одному битрейту и устаревший битрейт предыдущего трека после crossfade.

## Что не доказано без телефона

В коде не найдено фиксированного значения 192 kbps для всех песен. Ошибка подписи/клиента даёт конкретное основание для fallback, но не доказывает, какой HTTP-ответ был на устройстве пользователя. Наличие FLAC зависит от аккаунта, подписки, трека и API. Используется только raw; зашифрованный encraw не передаётся AVPlayer и не объявляется поддерживаемым. Настройка не превращает старый импортированный MP3/AAC в lossless и не гарантирует lossless на Bluetooth-выходе.

## Как получить проверяемое объяснение

После обновления выбрать Lossless повторно и воспроизвести несколько разных треков. Плеер → бейдж качества → Настройки качества звука → Диагностика → Скопировать диагностику качества. Отчёт содержит предпочтение, полученный формат, backend, HTTP-статусы, предлагаемые legacy варианты и решение о кеше; без OAuth-токенов, подписей, ключей и URL потока. Тогда можно различить отказ запроса, отсутствие FLAC у источника и офлайн-кеш.

## Полноэкранность

Возвращён fullScreenCover во всех точках открытия, без detents системного sheet. Для системного интерактивного смахивания используется native zoom navigation transition с matched источниками. Фон и видео занимают область вокруг Dynamic Island и до нижнего края; управляющие элементы используют safe-area inset. Физическую чёрную область Dynamic Island приложение не закрашивает. Закрытие не останавливает аудио.

## Верификация

Ссылки и SHA256 закреплены в yandex-stream-contract-reference.json. Fixture — yandex-stream-signature-fixture.json. Локальная регрессионная проверка охватывает всю существующую Python-сюиту; macOS/Swift/CryptoKit и Xcode проверяются в Build IPA. Live API для аккаунта пользователя здесь не вызывался: его учётные данные не предоставлены и не запрашивались.
